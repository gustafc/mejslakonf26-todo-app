# Migration reference

## SQL style

- Lowercase keywords, snake_case identifiers, singular table names (`todo`, not `todos`).
- Explicit `null` / `not null` on every column you add.
- Portable SQL only. H2 is used locally and in tests, but the client runs PostgreSQL. Avoid
  H2-specific syntax and functions.

## Type mapping

| Java                 | SQL                          |
|----------------------|------------------------------|
| `Long` id            | `bigint generated by default as identity primary key` |
| `String`             | `varchar(n)`, with n matching the `@Size` limit |
| `boolean`            | `boolean`                    |
| `LocalDate`          | `date`                       |
| `Instant`            | `timestamp with time zone`   |
| `enum` (as string)   | `varchar(50)` + `@Enumerated(EnumType.STRING)` |

Spring Boot's default naming strategy maps `dueDate` to `due_date`, so don't add
`@Column(name = ...)` just for that.

## Adding columns to existing tables

Tables may already contain rows in the client's environments.

- Nullable column: plain `alter table ... add column ...`.
- Not-null column: add it with a `default`, or in two migrations (add nullable and backfill, then
  set not null). Never add a bare not-null column without a default.

Example:

```sql
alter table todo add column due_date date null;
```
